# Локальный Whisper

Локальная веб-студия для расшифровки русских и английских аудио- и
видеофайлов. Записи, проекты, настройки и результаты остаются на этом
компьютере.

## Установка на другом компьютере

Публичный репозиторий: [romolego/whisper-studio](https://github.com/romolego/whisper-studio).
В нём сохраняется код оболочки, интерфейс, установщик, тесты и инструкции.
Проекты, записи, результаты, настройки, токены и сами модели в него не входят.

Для восстановления скачайте репозиторий через **Code → Download ZIP**,
распакуйте, запустите `Установить Whisper.bat`, затем `Запустить Whisper.bat`.
Установщик скачает зависимости и открытые модели и подключит их автоматически.
Установщик выбирает CPU или NVIDIA автоматически. На новой установке разметку
спикеров выполняет Nemotron без личного токена; Pyannote доступен дополнительно.

Для агента: прочитать [AGENTS.md](AGENTS.md) и [INSTALL.md](INSTALL.md), затем
запустить из корня проекта:

```powershell
# Пробная установка на процессоре
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install.ps1 -Device cpu
# Автоматический выбор CPU/NVIDIA
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install.ps1 -Device auto
# NVIDIA с проверкой ускорения
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install.ps1 -Device cuda
```

CPU использует те же модели и функции, но скорость зависит от процессора.
Для GPU установщик скачивает библиотеки CUDA/cuDNN и CUDA-сборку PyTorch;
работающий драйвер NVIDIA должен быть установлен. Подробности вариантов CUDA,
проверки и готовый запрос агенту — в [INSTALL.md](INSTALL.md).
Состав резервной копии — в [RESTORE.md](RESTORE.md).

Сохранённая на GitHub версия меняется только после нового коммита и `git push`.
Перед рискованными экспериментами сохраняйте рабочие изменения.

## Запуск

Дважды нажмите `Запустить Whisper.bat`. После запуска автоматически откроется
страница `http://127.0.0.1:3000`.

На новой машине сначала `Установить Whisper.bat` — он проверит, чего не хватает,
доставит недостающее и проверит компоненты. Если есть `data/test-ru.wav`,
он также распознает тестовую запись и измерит настоящую скорость.
Повторный запуск безопасен: установщик доделывает то, что не
вышло с первого раза, и не трогает то, что уже стоит. Отдельно то же самое
показывает `Проверить Whisper.bat`.

Для завершения работы нажмите `Остановить Whisper.bat` либо наведите курсор
на статус `Сервис работает` и выберите `Остановить и закрыть`.

## Проекты и очередь

- Один проект может содержать любое число файлов.
- Принимаются аудио и видео в любых форматах, которые открывает FFmpeg.
- Перед очередью файл анализируется; для видео с несколькими аудиодорожками
  можно выбрать нужную дорожку и прослушать её 30-секундное превью из начала,
  первой минуты, четверти, середины или последней четверти файла.
- Кнопка `Обрезать начало и конец` открывает редактор границ: звуковая дорожка
  столбиками громкости, по которой можно и слушать, и резать. Пока редактор
  открыт, быстрое 30-секундное превью прячется — оно вернётся по `Свернуть`.
  - Клик по дорожке ставит курсор прослушивания, его же можно тащить мышкой.
    Кнопка `▶` играет с текущего места, время идёт по самой дорожке.
  - Границы двигаются только за свои ручки, поэтому клик ради прослушивания
    их не сбивает. Кнопки `Начало здесь` и `Конец здесь` ставят границу туда,
    где стоит курсор: послушал — отметил.
  - Время можно вписать вручную в формате `мм:сс`, а ручки понимают стрелки
    клавиатуры: шаг — секунда, с Shift — полминуты. Отрезанные края серые.
  - `Скачать фрагмент` сохраняет выбранный кусок в MP3 — ровно тот же, что
    уйдёт в распознавание.
  - В очередь и в Whisper уходит только выбранный кусок, поэтому две минуты из
    часовой записи распознаются за минуты вместо часа. Таймкоды в результате
    остаются от начала исходного файла: `12:34` в тексте — это `12:34`
    в записи.
- Файлы автоматически обрабатываются в порядке добавления.
- Очередь единая для всех проектов: можно подготовить сразу несколько проектов
  и оставить компьютер работать.
- Любой файл можно остановить: `Снять с очереди` для ожидающего и
  `Остановить` для того, который распознаётся прямо сейчас. Кнопка есть в
  верхней строке очереди и на карточке файла в проекте.
- Остановка не удаляет исходник: файл получает статус `Остановлено`, и кнопка
  `В очередь` запускает его заново с самого начала. Готовый результат
  остановкой не затрагивается.
- Остановка выполняющегося файла срабатывает за секунду-две. Если файл ещё
  готовится к распознаванию, остановка ждёт окончания подготовки — на
  многочасовой записи это до пары минут.
- Готовые файлы проекта автоматически объединяются в общий результат.
- Проекты можно переименовывать, удалять и распределять по папкам.
- Кнопка `Выбрать` в списке включает режим выделения: клик по карточке отмечает
  проект, а не открывает его. Выделенные можно разом перенести в папку, вынуть
  из папок или удалить. `Выделить все` берёт только проекты, видимые при текущем
  фильтре папки. Отказ по одному проекту не отменяет остальные: если проект
  занят скачиванием по ссылке или распознаванием, он пропускается с причиной, а
  остальные обрабатываются.
- Список отображается общей лентой либо группами по папкам.

## Видео по ссылке

Квадратная кнопка со значком ссылки на странице проектов открывает загрузчик.
Он принимает публичные ссылки YouTube, VK, RuTube, Яндекс.Диска, Google
Drive и Zoom. Перед скачиванием сервис показывает название, длительность и доступные
варианты качества, а также позволяет выбрать папку и название проекта.

Для Zoom рядом с полем ссылки появляется поле `Код доступа`: запись закрыта
кодом, который выдают вместе со ссылкой, а не передают в самой ссылке. Код
нужен и для проверки ссылки, и для загрузки; он хранится в состоянии загрузки,
чтобы докачка после перезапуска не упиралась в форму пароля, и не отдаётся в
браузер в ответах API.

**Как это работает.** Zoom в 2026 году сменил механику: старая ручка проверки
пароля `validate_meet_passwd` отвечает `This API has been deprecated`, а страница
записи редиректит на `/rec/component-page` с `componentName=need-password`.
Экстрактор yt-dlp за этим не поспел и падает с «Unable to extract data»
([issue yt-dlp#16377](https://github.com/yt-dlp/yt-dlp/issues/16377),
воспроизводится и на 2026.07.04).

Поэтому проверка кода проходится самостоятельно в
[backend/zoom_access.py](backend/zoom_access.py): запрос уходит на новый адрес
`/nws/recording/1.0/validate-meeting-passwd` формой (на JSON Zoom отвечает
«Missing Request Parameters»), а полученная сессия отдаётся yt-dlp файлом
cookies — дальше он извлекает запись обычным путём. Когда yt-dlp починит свой
экстрактор, модуль можно будет убрать, остальное останется на месте.

Для YouTube отдельного поля не появляется, но сервис умеет обходить его
бот-проверку. «Sign in to confirm you're not a bot» приходит на запрос, а не на
видео: адрес попал под подозрение, и веб-клиент требует вход. Тот же ролик
обычно отдаётся, если спросить его от имени другого клиента API — у мобильных
и телевизионных приложений своя ручка, и проверки на ней нет. Поэтому
[backend/youtube_access.py](backend/youtube_access.py) держит очередь способов,
[backend/video_downloader.py](backend/video_downloader.py) перебирает их молча,
а сработавший запоминается на полчаса, чтобы следующая ссылка пошла сразу через
него. Оттуда же лечится «Requested format is not available» на живом видео: это
не «нет такого качества», а форматы, которые yt-dlp прячет, потому что YouTube
требует за них одноразовый токен (PO token) — в запасной попытке фильтр
снимается.

Когда не проходит ни один способ, вместо английской трассы со ссылками на
GitHub показывается объяснение и что делать. Обычно ограничение снимается само
за 10–20 минут. Если нужно сейчас, помогают cookies: файл `cookies.txt`,
выгруженный из браузера расширением, кладётся в папку `data/cookies`
(`Настройки → Хранение на диске → Папка для cookies`, инструкция лежит там же).
Второй путь — `Настройки → Хранение на диске → Cookies YouTube из браузера`:
тогда они берутся из установленного браузера. По умолчанию выключено, и это
намеренно: cookies привязывают загрузки к личному аккаунту Google, а YouTube за
выгрузки аккаунт может ограничить, поэтому решение остаётся за владельцем. На
Windows читается только Firefox — Chrome, Edge и Opera с 2024 года шифруют свою
базу привязкой к приложению, и прочитать её со стороны нельзя.

Флажок `Только скачать, без расшифровки` забирает запись, не занимая очередь
распознавания: файл ложится в проект готовым и ждёт, пока его поставят в
очередь вручную. Это нужно, когда ссылок много, а расшифровывать их хочется
потом и выборочно.

Качество по умолчанию задаётся в `Настройки → Хранение на диске → Качество
скачивания по ссылке`. По умолчанию это «Только звук»: для расшифровки его
достаточно, а весит он в десятки раз меньше видео. Точного совпадения с
настройкой обычно нет — у каждого видео свой набор высот, поэтому берётся
ближайшее качество не выше выбранного, а если все доступные выше, то самое
низкое из них. Выбрать другое качество для конкретного видео можно всегда.

Когда просят только звук, а отдельной аудиодорожки у источника нет, скачивается
совмещённый файл, и видеоряд снимается с него сразу после загрузки — дорожка
переносится как есть, без перекодирования. Так ведёт себя полный HLS у VK и
YouTube, когда единственный работающий клиент предлагает один прогрессивный
формат 360p: на многочасовой записи это разница втрое по месту на диске.

Прогресс сохраняется на диск. Загрузку можно поставить на паузу, продолжить с
сохранённого места или остановить с удалением недокачанного файла. При обрыве
сети сервис пытается продолжить автоматически; после перезапуска незавершённая
активная загрузка восстанавливается. Готовый файл сразу ставится в общую
очередь транскрибации с текущими настройками по умолчанию.

## Настройки

Сервис запоминает:

- язык и режим распознавания по умолчанию;
- модель разметки спикеров по умолчанию: Pyannote или Nemotron 3;
- вариант таймкодов;
- текст со знаками препинания или без них;
- шаблон названия нового проекта;
- единый способ добавления файлов: копировать либо оставлять на месте;
- сохранять ли извлечённое аудио в проекте;
- основной формат экспорта;
- режим списка проектов;
- светлую или тёмную тему.

## Результаты

Отдельный файл и объединённый результат проекта можно скопировать в буфер
обмена или скачать в форматах DOCX, MD, TXT, SRT, VTT и JSON.

### Готовые файлы лежат в проекте сами

Заходить в интерфейс за результатом не нужно. Как только файл распознан, рядом
с проектом появляются три файла с одинаковым именем — `Название проекта —
расшифровка.md`, `.txt` и `.docx`. Они переписываются после каждого нового
файла в проекте, после разметки спикеров и после переименования спикера,
поэтому в папке никогда не лежит вчерашняя версия. Путь к папке проекта
открывается кнопкой `Показать в папке`.

Вид этих файлов берётся из настроек просмотра — таймкоды и знаки препинания
такие же, как выбраны для просмотрщика. Разметка по спикерам включается всегда,
когда она есть: переключатель в просмотрщике можно щёлкать туда-сюда, а файл на
диске должен нести всё, что о записи известно.

При переименовании проекта файлы переименовываются вместе с ним; брошенный
файл со старым именем удаляется, чтобы в папке не лежали две расшифровки одной
записи. Удаляются только файлы с суффиксом ` — расшифровка`, всё остальное в
папке принесено человеком и не трогается. Если файл открыт в Word, Windows не
даст его перезаписать — это не считается ошибкой распознавания, задание всё
равно завершится, а файл обновится при следующем изменении проекта.

### Абзацы, а не лесенка

Whisper режет речь по своему окну: сегмент — это 2–10 секунд, 30–150 знаков, и
граница между ними приходится куда попало, часто посреди мысли. Раньше это
выходило наружу как есть, в двух одинаково неудобных видах: без таймкодов вся
запись склеивалась одной строкой на десятки тысяч знаков, с таймкодами — рваной
лесенкой по пять слов на строку.

Теперь сегменты собираются обратно в абзацы, и граница ставится там, где она
есть в самой речи: на смене спикера, на паузе от трёх секунд, на первой точке
после 400 знаков. Если модель не расставила знаков совсем, абзац всё равно
рвётся на 1200 знаках — иначе такой файл снова стал бы стеной. Замер на реальных
записях: часовое совещание из 169 сегментов даёт 107 абзацев с медианой в 333
знака, полуторачасовой разговор из 462 сегментов — 147 абзацев по 198 знаков.

Режим `таймкоды по фразам` строку на фразу сохраняет — ради этого его и
выбирают, — но абзацы в нём отделяются пустой строкой. Границы считаются по
исходному тексту модели, до снятия пунктуации, поэтому в режиме `Без знаков`
абзацы ровно те же: иначе удалённые точки унесли бы с собой и разбиение.

Это же разбиение работает в просмотрщике, в буфере обмена и во всех форматах —
код один, [backend/paragraphs.py](backend/paragraphs.py).

В просмотрщике независимо переключаются:

- таймкоды: без таймкодов, по фразам либо по словам;
- знаки препинания: сохранять либо убрать;
- разметка по спикерам: показывать либо скрывать.

Кнопки `Копировать полный текст` и `Скачать полный` включают все реплики и
имена размеченных спикеров. Фильтр спикеров и переключатель `Без спикеров`
меняют только просмотр. Для отдельной выборки есть сворачиваемый пункт
`Экспорт выбранных спикеров`; частичная выгрузка отмечается в имени файла,
а в TXT, MD и DOCX — также в самом документе.

Имя спикера автоматически сохраняется при переходе к другому спикеру или
клике вне поля; поле закрывается сразу. Enter и галочка также сохраняют имя,
Escape отменяет правку. Имя хранится для конкретного файла и одинаково
используется в просмотре, копировании и всех форматах экспорта.

### Послушать спикера

«СПИКЕР 3» с репликой «да, давайте так» может оказаться кем угодно, а на слух
голос узнаётся за пару секунд. Поэтому у каждой карточки спикера в правом
нижнем углу есть кнопка `▶`: она проигрывает образец голоса — до четырёх самых
длинных реплик этого спикера из разных мест записи, по восемь секунд, с
короткими паузами между ними. Длинные реплики берутся потому, что в них голос
звучит чисто, без чужих «угу» по краям; несколько кусков вместо одного —
потому что ошибку разметки так слышно сразу. Повторный клик останавливает.

Образец режется из сохранённого аудио, а если его нет — из исходника и
выбранной в нём дорожки. Собирается он за доли секунды и кешируется во
временной папке, пока разметка файла не поменяется. Код —
[backend/speaker_samples.py](backend/speaker_samples.py).

### Две модели разметки спикеров

Спикеров размечает одна из двух локальных моделей:

- **Pyannote Community-1** — прежняя, проверенная. Требует токена Hugging Face
  для первой загрузки, на видеокарте занимает около 5.3 ГБ.
- **NVIDIA Nemotron 3 Diarization** (сентябрь 2026) — различает до восьми
  голосов, размечает перебивания, занимает около 1.4 ГБ видеопамяти. Открытая,
  токен не нужен.

Модель по умолчанию выбирается в `Настройки → Распознавание → Модель
спикеров`. Для отдельного файла её можно выбрать в списке `Спикеры` при
постановке в очередь, при загрузке по ссылке и при точном перераспознавании.
Готовый файл можно разметить заново другой моделью кнопкой `◐ Спикеры
заново` в его карточке: Whisper при этом не перезапускается, текст остаётся
прежним, меняются только метки спикеров. Имена, присвоенные спикерам, при
этом сбрасываются — у новой разметки своя нумерация.

Выбранная, но не готовая модель — это отказ с объяснением, а не тихая замена
другой: если Nemotron выбрали ради сравнения, подмена на Pyannote испортила бы
сравнение. Файлы, размеченные до появления выбора, считаются размеченными
Pyannote, и повторная разметка по ним без явного выбора остаётся на нём.

Замер на 1 ч 55 мин совещания (GTX 1060 6 ГБ, один и тот же текст Whisper):
Nemotron разметил запись за 48 секунд целиком, включая загрузку модели.
Pyannote нашёл 7 голосов, Nemotron — 8, из которых один занял две секунды и
похож на шум. По времени речи разметки совпали на 89%: каждому спикеру
Pyannote соответствует один спикер Nemotron в 83–92% его речи.

Nemotron работает в той же среде, что и Pyannote: ему нужен тот же torch.
Поддержку модели влили в transformers 23.09.2026, после выпуска 5.17.0,
поэтому в `requirements-diarization.txt` transformers закреплён коммитом из
исходников. Спектрограмма считается кусками по десять минут и совпадает с
проходом по всей записи бит в бит, поэтому память не растёт с длиной записи.
Код — [backend/nemotron_worker.py](backend/nemotron_worker.py).

Слова сопоставляются со спикерами через индекс реплик по времени. Раньше на
каждое слово перебирались все реплики: на двухчасовой встрече это 17 тысяч
слов на две тысячи реплик и 23 секунды. С индексом — 0.4 секунды при
идентичном результате.

## Диктовка не ждёт длинных файлов

Диктовка обрабатывается отдельно от очереди файлов и получает видеокарту, не
дожидаясь окончания транскрибации: файл уступает её на ближайшем сегменте.
Замер на 15-минутной записи — диктовка дождалась своей очереди за 1.3 секунды,
хотя файл считался 97 секунд. Раньше она стояла в общей очереди и на
шестичасовой записи ждала до 54 минут.

Единственное, чего диктовка всё-таки ждёт, — разметка спикеров: это отдельный
процесс Pyannote или Nemotron, прервать его посередине нельзя. В такой момент в карточке
фрагмента прямо написано, чего он ждёт.

Модели держатся в памяти по языкам, поэтому смена языка больше не стоит
перезагрузки: раньше переключение на английский добавляло 33 секунды каждый
раз. Перед разметкой спикеров модели выгружаются — Pyannote пикует на 5360 МиБ
из 6144, и вместе они бы не поместились.

В карточке готового файла видно, на чём считал Whisper. Если там написано
«процессор», значит видеокарта была недоступна и распознавание шло примерно в
20 раз медленнее.

## Модели и зависимости

Раздел `Настройки → Модели и зависимости` показывает, из чего собран сервис. По
каждому компоненту видно четыре вещи: нужен ли он, есть ли он, где лежит и
откуда скачан. В подсказке — путь, ссылка на источник, дата установки и команда
установки, если ставить придётся руками.

Компоненты разделены на обязательные и необязательные, и это честное деление.
Без русской модели не работает ничего. Без английской работают русские файлы, без
Pyannote — всё кроме разметки спикеров, без видеокарты всё считается на
процессоре примерно в двадцать раз медленнее. Поэтому у каждого компонента
написано не «установлен / не установлен», а что именно перестанет работать.

Что сервис умеет поставить сам:

- **модели Whisper** — кнопка `Скачать` в этом же разделе. Загрузка идёт с
  Hugging Face с прогрессом, скоростью и остатком времени и продолжается с места
  обрыва, если связь пропадёт.

Программы — Python, FFmpeg, Node.js, PowerShell 7 — ставит `Установить
Whisper.bat` через `winget`. Тот же список с командами показан в разделе на
случай, если ставить придётся вручную; драйвер NVIDIA всегда ставится руками.

Pyannote требует аккаунта Hugging Face и принятия условий модели, поэтому он
активируется отдельно в разделе `Спикеры`. При переносе с уже работающей машины
модель едет в архиве, и token на новой машине не нужен.

Nemotron 3 открытый: установщик скачивает его сам (около 400 МБ), а если не
вышло — в разделе `Спикеры` есть кнопка `Скачать модель` с прогрессом. Пакеты
для него (`transformers` и `librosa`) ставятся в среду разметки спикеров; на
машине, где эта среда уже была, повторный запуск `Установить Whisper.bat`
доставит их, не трогая torch с CUDA.

## Перенос на другую машину

`Собрать архив для ноутбука.bat` на работающей машине складывает переносимую
копию рядом с проектом и пакует её в zip. На новой машине копию достаточно
распаковать и запустить `Установить Whisper.bat`.

В архив едет всё, что иначе качалось бы на новой машине: модели Whisper,
модели Pyannote и Nemotron из кеша Hugging Face, собранный интерфейс, `node_modules` и
колёса Python — и для сервиса, и для torch с Pyannote. Из сети на новой машине
остаются только четыре программы через `winget`: Python 3.11, Node.js, FFmpeg и
PowerShell 7.

Не едет то, что привязано к конкретной машине: сами среды Python, библиотеки
CUDA из `vendor`, логи и PID-файлы. Записи и база остаются дома — с ключом
`--with-data` поедут и они. Ключ `--lean` собирает архив без пакетов: он в
полтора раза меньше, но установка на месте будет качать около гигабайта.

Колёса складываются в `bundle/` внутри проекта и переживают пересборку архива,
так что второй раз тот же гигабайт не качается. `--refresh-wheels` обновляет их
принудительно.

Набор колёс собран под Windows x64 и Python 3.11 — ту связку, которую тянет
установщик, так что совпадение гарантировано. Полагаться на это вслепую всё же
нельзя: если чего-то в наборе не хватит, установщик доберёт недостающее из сети
вместо того, чтобы молча упасть.

Отдельная среда для разметки спикеров создаётся под ту машину, на которую
ставится. Там, где есть поддерживаемая NVIDIA, установщик создаёт
`.venv_diarization_gpu` с CUDA-сборкой torch. Там, где её нет,
установщик создаёт `.venv_diarization_cpu` с процессорной сборкой — около 250 МБ
вместо 2.5 ГБ, потому что CUDA-часть на такой машине всё равно мертвый груз.

### Чего ждать от машины без видеокарты

Замер на этой машине, один и тот же трёхминутный отрезок и одна и та же модель:
видеокарта GTX 1060 — 16.3x реального времени, процессор Xeon E3-1240 v2 —
0.83x. Разрыв ровно двадцатикратный, и это та самая цифра, которая написана
рядом с компонентом «Драйвер NVIDIA».

Две вещи из этого замера стоит знать заранее:

- **Режим «быстро» на процессоре не помогает.** `beam_size=1` дал те же 0.77x
  против 0.83x при `beam_size=5`. У turbo всего четыре слоя декодера, всё время
  съедает энкодер, а он от ширины поиска не зависит. Привычный обмен качества на
  скорость здесь просто не работает.
- **Гиперпоточность мешает.** Восемь потоков на четырёх ядрах дали 0.76x против
  0.83x на четырёх. Поэтому число потоков берётся по физическим ядрам, а не по
  логическим; переопределяется переменной `WHISPER_CPU_THREADS`.

Двадцатикратный разрыв — свойство пары «эта видеокарта, этот процессор», а не
процессоров вообще. Xeon E3-1240 v2 — Ivy Bridge 2012 года без AVX2: у него
256-битными стали только вещественные операции, а целочисленные, на которых и
держится int8, остались 128-битными. Любой процессор после 2013 года считает ту
же модель примерно вдвое быстрее на том же такте, а с AVX-512 VNNI — ещё вдвое.
`Проверить Whisper.bat` печатает, какие расширения нашлись, рядом со скоростью.

## Что хранится на диске

### Папка называется как проект, файл — как запись

```
data\sessions\2026 - 08 - 14 - Показ релиза\
    2026 - 08 - 14 - Показ релиза — расшифровка.md
    2026 - 08 - 14 - Показ релиза — расшифровка.txt
    2026 - 08 - 14 - Показ релиза — расшифровка.docx
    media\GMT20260814-060149_Recording.mp4     копия исходника
    audio\GMT20260814-060149_Recording.wav     дорожка, которую слышал Whisper
    outputs\GMT20260814-060149_Recording.txt   и .md .docx .srt .vtt .json
```

Раньше на этих местах стояли идентификаторы: папка проекта называлась
шестнадцатеричным `90240cb9e41145e0a1c37a4e2fff5032`, копия видео — таким же
идентификатором записи, а результаты лежали в подпапке с идентификатором
задания. Внутри сервиса это удобно, снаружи бесполезно: нужную расшифровку в
проводнике было не найти.

Проекты, созданные до этого правила, переименовываются при первом запуске
сервиса. Проход идемпотентный и переживает сбой: файл, который не удалось
переложить (открыт в плеере, держит антивирус), остаётся на месте и переедет
при следующем запуске.

Несколько мелочей, которые видно не сразу:

- **Два проекта с одинаковым названием** разойдутся на диске номером —
  `Планёрка` и `Планёрка (2)`, как это делает сам проводник.
- **Windows не принимает** символы `<>:"/\|?*` в имени, молча срезает пробел
  и точку в конце и не даёт создать файл с именем `CON` или `LPT1`. Всё это
  снимается автоматически, поэтому проект можно называть как угодно.
- **Имена режутся до 80 знаков.** Полный путь в Windows ограничен 260, а в него
  должны поместиться и папка проекта, и имя файла.
- **Переименование проекта переносит папку** и переписывает все пути в базе.
  Пока файл распознаётся или идёт скачивание по ссылке, папка не трогается:
  Windows не даст переименовать каталог, из которого сейчас читают. Название
  проекта меняется сразу, папка догоняет по окончании работы.
- **Исходники в режиме «оставлять на месте»** лежат вне проекта, и переезд
  папки их не касается.

Whisper распознаёт не видео, а извлечённую из него аудиодорожку. Отсюда две
независимые настройки, и вместе они решают, сколько места займёт проект.

`Добавление файлов` — что делать с исходником:

- `Копировать в проект` — файл целиком уезжает в папку проекта. Час видео это
  несколько гигабайт.
- `Оставлять на месте` — в проекте хранится только путь к исходнику. Если файл
  потом переместят или удалят, расшифровка останется: она уже готова.

`Сохранять извлечённое аудио` — что делать с дорожкой, которую слышал Whisper:

- `В проекте` — дорожка остаётся в `data\sessions\<проект>\audio`. Час записи в
  моно 16 кГц весит около 115 МБ.
- `Не сохранять` — дорожка живёт во временной папке только во время
  распознавания и удаляется сразу после, как было раньше.

Сочетания работают независимо. Самый экономный вариант — `Оставлять на месте` и
`В проекте`: тогда в проекте лежит путь к исходному видео и аудио на 115 МБ
вместо копии видео на три гигабайта.

Оба пути видны в карточке файла внутри проекта: строка исходника и строка
извлечённого аудио, у каждой кнопка `Показать в папке`. Аудио можно удалить
отдельной кнопкой — расшифровка при этом остаётся.

Видео, скачанное по ссылке, всегда остаётся в проекте: удалять его сервис не
берётся. Настройка сохранения аудио на такие файлы действует так же.

Перетаскивание файлов мышью всегда копирует их в проект, даже в режиме
`Оставлять на месте`: браузер передаёт только содержимое файла, без пути на
диске. Сервис об этом предупреждает. Чтобы файлы остались на месте, добавляйте
их кнопкой выбора файлов — она открывает обычное окно Windows и получает пути.

## Подключённые сервисы

Другие программы на этом компьютере могут пользоваться этим Whisper как
транскрибатором. Сейчас подключены двое: Анализ вебинаров
(`E:\WebinarAnalyzer-portable-2026-07-29`) с заголовком
`X-Whisper-Integration: webinar-analyzer-local` и телеграм-бот с заголовком
`telegram-bot-local`.

Каждый такой сервис получает свою папку в списке проектов — `Анализ вебинаров`, —
и один проект на каждый проект внешнего сервиса, а не одну общую свалку. В общей
ленте, где папок не видно, рядом с названием стоит метка сервиса: чужую
расшифровку не спутать со своей.

Список сервисов виден в `Настройки → Подключённые сервисы`: сколько проектов и
файлов пришло от каждого и когда он обращался последний раз.

**Папку внешнего сервиса нельзя удалить.** Сервис создал бы её заново при
следующем обращении, а вместе с папкой ушли бы расшифровки, которых в самом
сервисе может уже не быть. Переименовать папку можно — она останется папкой
сервиса. Обычные папки удаляются как раньше.

Чтобы чужие расшифровки не забивали общую ленту, в том же разделе есть
переключатель `Проекты сервисов в общей ленте`. По умолчанию они **скрыты**:
приходят пачками, а нужны редко. Скрытый сервис уходит с экрана проектов
целиком — и проекты, и папка слева, — потому что папка без содержимого только
занимает строку и сбивает с толку. Ничего при этом не удаляется: `Показывать`
возвращает и папку, и всё, что в ней лежит, а в управлении папками она видна в
любом случае. Побочный, но полезный эффект: пока проекты скрыты, `Выделить все`
их не захватывает, поэтому пакетным удалением их не снести случайно.

Добавить второй или третий сервис — это одна запись в `REGISTRY` в
[backend/integrations.py](backend/integrations.py). Разделение по папкам, метка в
ленте и учёт в настройках подхватятся сами.

## Локальные дополнения

Telegram-бот и Android-приложение для подготовки аудио не входят в публичную
резервную копию студии. Их код, настройки и скрипты сохраняются отдельно.

## Полнота распознавания файлов

Загруженные файлы передаются Whisper целиком, без предварительного удаления
участков фильтром VAD. Такой фильтр определяет обычную речь и может принять
пение или тихий голос за фон: на песне длиной 319.68 с прежний режим оставлял
модели только 135.744 с. Размер MP3 и извлечение дорожки к этому пропуску
отношения не имели.

Настоящие повторы фраз разрешены, включая припевы. При этом перенос текста
между окнами остаётся выключенным, а известные галлюцинации очищаются после
распознавания. Дословное эхо подсказки удаляется только при низкой уверенности
во всех словах; удалённые вставки сохраняются в JSON для проверки. Полная
передача аудио устраняет отсечение до модели, но не гарантирует правильного
распознавания каждого слова в пении и шуме.

В JSON нового результата записывается `transcription_profile: full-audio-v1`.
Старые готовые результаты обновляются через повторное распознавание.
Незавершённые окна прежнего профиля с VAD не используются при продолжении.

## Длинные записи

Ограничения на длительность и размер файла нет, и это защищено механикой, а не
надеждой.

**Память.** faster-whisper держит файл в памяти целиком: сначала весь звук во
float32, затем мел-спектрограмму — тоже сразу
по всему файлу. Замер на плотной речи: пик 6818 МБ на два часа, то есть около
**3.4 ГБ на час записи**, и скачок даёт именно расчёт спектрограммы. Прямым
проходом это упирается в потолок на 8–9 часах даже при 32 ГБ памяти.

Поэтому записи длиннее 45 минут обрабатываются окнами по 30 минут. Пик памяти
перестаёт зависеть от длины файла и держится около 1.7 ГБ и на двух часах, и на
ста. Файлы короче порога идут прежним путём, одним проходом.

Перед каждым окном модель получает 12 секунд разгона — акустический контекст до
своей границы, чтобы слово на стыке не разорвалось. Владелец сегмента
определяется по его середине, поэтому разгон ничего не дублирует и ничего не
теряет.

**Защита работы.** После каждого окна результат дописывается на диск в
`checkpoint.json` рядом с выводами задачи. Если пропало питание или сервис
перезапустили, распознавание продолжается с первого недоделанного окна, а не с
начала: цена сбоя — не больше одного окна работы вместо всей расшифровки. Запись
чекпоинта идёт во временный файл с переименованием, поэтому обрыв посреди самой
записи не превращает его в мусор.

Чекпоинт привязан к отпечатку исходника и настроек распознавания. При смене
файла, языка, качества, дорожки или границ обрезки он отбрасывается — иначе
результат стал бы смесью двух разных прогонов.

**Размер.** Извлечённое аудио пишется с `-rf64 auto`: обычный WAV хранит размер в
32-битном поле и ломается после 4 ГБ, что при 16 кГц моно наступает примерно на
37 часах записи. Контейнер переключается на RF64 только когда предел
действительно достигнут, поэтому короткие файлы остаются обычным WAV.

## Знаки препинания

Русская дообученная модель без явной инструкции выдаёт текст без пунктуации и
заглавных букв. Поэтому сервис всегда просит модель оформлять результат как
обычный текст — и при распознавании файлов, и в диктовке. Замер на 180 секундах
реальной записи: без инструкции знаки были в 0% сегментов, с инструкцией — в
100%, при том же числе слов и том же времени работы.

Инструкция передаётся через `hotwords`, а не `initial_prompt`: второй попадает
только в первое 30-секундное окно и дальше теряется, потому что перенос
контекста между окнами намеренно выключен (он провоцирует зацикливание).

Переключатель `Со знаками / Без знаков` работает уже после распознавания: JSON
хранит оригинальный текст модели, поэтому вид можно менять в любую сторону без
повторного прогона.

## Мусор из обучающих данных Whisper

Whisper учили на видео с YouTube вместе с их субтитрами, поэтому в тишине,
музыке и шуме модель не молчит, а дописывает самый вероятный шаблон из
обучающих данных: подпись автора субтитров (`Субтитры сделал DimaTorzok`,
`Редактор субтитров А.Синецкая Корректор А.Егорова`), тег звука
(`ВЕСЕЛАЯ МУЗЫКА`, `[аплодисменты]`, `♪♪♪`) или титр (`Продолжение следует…`).
В записи этих фраз не было.

Такие вставки снимаются автоматически — и в транскрибации, и в диктовке, и во
всех форматах экспорта. Подпись, приклеенная хвостом к настоящей фразе,
обрезается, а сама фраза остаётся. Снятое не пропадает: оно лежит в поле
`removed_hallucinations` файла JSON, поэтому всегда видно, что именно убрали и
по какой причине.

Прощания, которые бывают и настоящей речью — «спасибо за внимание»,
«подписывайтесь на канал», «всем пока» — **не удаляются**. В докладах и в
видео с YouTube это содержание записи, а не галлюцинация, и отличить одно от
другого по тексту невозможно. Если для каких-то материалов их всё же нужно
убирать, в `backend/hallucinations.py` есть переключатель
`REMOVE_AMBIGUOUS_OUTRO`.

Результаты, полученные до появления фильтра, чистятся на лету при просмотре и
экспорте. Файлы в `data\sessions\*\outputs\` при этом остаются как были;
переписать их можно отдельно:

```
.venv\Scripts\python.exe -m scripts.clean_hallucinations           # отчёт
.venv\Scripts\python.exe -m scripts.clean_hallucinations --apply   # переписать
```

Сервис использует среду `.venv_diarization_gpu` с CUDA-сборкой PyTorch и
считает разделение голосов на видеокарте. На этом компьютере это примерно в
20 раз быстрее процессора: 44 минуты записи размечаются за 5 минут вместо
полутора-двух часов. Если GPU-среда недоступна, сервис возвращается к
`H:\zvuk\.venv_diarization` и считает на процессоре.

На каком устройстве идёт разделение голосов, видно в разделе
`Настройки → Спикеры`. Если там написано «процессор», интерфейс отдельно
предупреждает, что расчёт будет долгим.

## Диктовка

В отдельном разделе «Диктовка» можно:

- записывать речь с микрофона с живой волной и таймером;
- остановить запись, дождаться локального распознавания и продолжить то же
  сообщение новым фрагментом неограниченное число раз;
- исправить и скопировать собранный текст;
- подтвердить сообщение кнопкой `OK` и сохранить его в истории;
- прослушать каждый исходный аудиофрагмент из текущего сообщения или истории;
- остановить распознавание фрагмента кнопкой `Остановить`: аудио остаётся на
  диске, а `Повторить` запускает распознавание заново.

Любой фрагмент можно убрать крестиком, не удаляя всё сообщение: его текст
исчезает из диктовки, аудио удаляется, а остальные фрагменты остаются. Если
фрагмент в этот момент распознаётся, сервис сначала останавливает его. Ручные
правки текста при этом сохраняются — вырезается только вклад убранного
фрагмента.

Готовую диктовку можно сохранить в проект: кнопка `Сохранить в проект` в режиме
правки сообщения истории. Каждый фрагмент становится отдельным файлом проекта с
уже готовой расшифровкой, аудио копируется. Диктовка остаётся в истории с
отметкой `сохранено в проект`, поэтому очистка истории больше не грозит потерей.

После остановки запись сначала сохраняется в аварийный буфер браузера, затем
переносится в `data\dictations` и лишь после этого передаётся Whisper.
Сбой распознавания не удаляет исходное аудио: фрагмент можно запустить
повторно. Подтверждение, копирование и правка текста тоже не удаляют запись.
Удаление происходит только при явном удалении сообщения с подтверждением.

Рабочие файлы находятся в `data`, модели — в `models`, журналы запуска — в
`logs`. База проектов, очереди и диктовок — `data\whisper.db`.
