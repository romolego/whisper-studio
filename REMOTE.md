# Удалённые вычисления Whisper Studio

Для обновления старой версии на ноутбуке и проверки агентом используйте
[LAPTOP_SETUP.md](LAPTOP_SETUP.md): сначала актуализируется вся студия из GitHub,
затем настраивается удалённый режим.

Ноутбук хранит проекты, извлекает нужную аудиодорожку, обрезает и нарезает
длинные записи, собирает и экспортирует результат. На основном компьютере
выполняются Whisper и выбранный движок спикеров (Nemotron или Pyannote).
Диктовка тоже использует выбранный компьютер. Дополнительная модель пунктуации
для режима полной large-v3 пока выполняется на ноутбуке.

Обычный «Запустить Whisper.bat» оставляет API на `127.0.0.1:8765` и не
открывает сетевой адаптер. На новой установке выбран локальный режим.
Включение адаптера не меняет режим вычислений основной студии.

## Один раз: связь через интернет

1. Установите [Tailscale для Windows](https://tailscale.com/docs/install/windows)
   на оба компьютера. Войдите в одну личную сеть Tailscale. Вход требует вашего
   участия, ключ Whisper его не заменяет.
2. В Tailscale на основном компьютере должна быть включена настройка
   **Allow incoming connections**. Обоим устройствам нужен доступ друг к другу
   по правилам вашей сети Tailscale. Перенаправлять порт на роутере не нужно.
3. Обновите код Whisper Studio на обоих устройствах. Если студия уже установлена,
   соберите интерфейс `npm.cmd run build` и перезапустите её, когда очередь пуста.
   Для новой установки используйте обычную инструкцию [INSTALL.md](INSTALL.md);
   на ноутбуке без NVIDIA выбирайте `-Device cpu`.

## Каждый раз: основной компьютер

Запустите **«Запустить удалённый GPU.bat»**. Он запускает обычную студию при
необходимости и включает отдельный адаптер на IPv4-адресе Tailscale, порт 8766.
В открытом окне появится код `ws1.…`, который также копируется в буфер обмена.
Храните код как пароль: он разрешает выполнять модели на этом компьютере.

Оставьте окно открытым на время работы. `Ctrl+C` выключает адаптер. При простом
закрытии окна доступ выключается автоматически не позднее чем через 35 секунд.
Уже начатый шаг модели завершается или отменяется в ближайшей доступной точке;
процесс внешней разметки прерывается. Сама локальная студия продолжает работать.
После перезапуска компьютера адаптер остаётся выключенным до явного запуска.

## Один раз: ноутбук

1. Запустите свою студию обычным способом.
2. Откройте **Настройки → Вычисления**, вставьте код и нажмите
   **«Проверить подключение»**. Проверка показывает связь, наличие моделей и
   доступность устройств; реальную работу модели проверяет расшифровка записи.
3. Нажмите **«Использовать удалённый компьютер»**. Код и выбор сохраняются
   на ноутбуке. При следующих запусках вводить тот же код не нужно.
4. Загрузите короткую запись и проверьте текст, спикеров и подпись устройства
   в результате: **«удалённая видеокарта»** или **«удалённый процессор»**.
   После этого запускайте длинные записи.

Работайте с файлами и результатами на ноутбуке как обычно. Сетевые копии аудио
на основном компьютере временные и удаляются после вычисления. Если сеть
оборвалась, сервер отменяет задание после 90 секунд без опроса. Для повторной
попытки запустите задачу снова: длинные записи сохраняют готовые окна локально.
Автоматической подмены удалённого устройства процессором ноутбука нет.

Чтобы считать на ноутбуке, выберите **«Использовать этот компьютер»**.
Сохранённое подключение останется. Начатое задание сохраняет свой выбранный
компьютер до завершения; смена настройки влияет на следующие задания.

## Очередь и ограничения

- Местная и удалённая студии делят доступ к моделям. Фоновые задания считают
  по одному, местная диктовка получает приоритет на границе сегмента Whisper.
  Разметка спикеров занимает устройство до завершения своего шага.
- Сетевой адаптер принимает до восьми заданий, включая выполняемые и результаты,
  которые клиент ещё не забрал. Из видео отправляется только подготовленное
  mono PCM WAV 16 кГц: примерно 115 МБ на час. Исходное видео не пересылается.
- Один сетевой запрос ограничен 2 ГиБ аудио (примерно 18 часов). Длинная
  транскрибация разбивается на окна; разметка спикеров передаёт аудио целиком
  и подчиняется этому пределу.
- Разметка использует устройство, настроенное в студии основного компьютера.
  Выбор CPU/CUDA на ноутбуке не меняет оборудование сервера. При `auto` сервер
  может использовать CPU; фактическое устройство Whisper возвращается в результат.
- Основной компьютер должен быть включён и не спать. Скорость передачи
  зависит от соединения, в том числе от прямого или ретранслируемого пути Tailscale.

## Домашняя сеть без Tailscale

Для одной доверенной локальной сети адрес задаётся явно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_remote.ps1 -BindAddress 192.168.1.10
```

Замените адрес на IPv4 основного компьютера. Код содержит этот адрес и порт:
при их изменении понадобится новый код. Сам ключ остаётся прежним.
Открывать адаптер на `0.0.0.0` или публичном IPv4 запрещено. HTTP внутри
Tailscale защищён сетевым шифрованием; обычный LAN-вариант предназначен для
доверенной домашней сети. Браузер ноутбука обращается только к своему локальному
API, поэтому доступ к проектам и настройкам через адаптер не предоставляется.

Если соединение не проходит, проверьте Tailscale, сон компьютера и брандмауэр
Windows. Проверить TCP-порт с ноутбука можно командой
`Test-NetConnection <адрес основного компьютера> -Port 8766`.
При необходимости разрешите входящий TCP 8766 только на адрес Tailscale и
только от Tailscale-адреса ноутбука; не отключайте брандмауэр целиком.

## Настройки и обслуживание

Постоянный серверный ключ находится в `data/remote-host.json`, сохранённое
подключение ноутбука — в `data/remote-client.json`. Они исключены из Git вместе
со всей папкой `data`. Не переносите их в публичный репозиторий и не передавайте
снимок окна с кодом посторонним.

Для отзыва ключа закройте адаптер, удалите только `data/remote-host.json` и
запустите адаптер снова. На ноутбуке введите новый код. Не удаляйте папку `data`.
Не копируйте `remote-client.json` ноутбука на основной компьютер: сервер должен
оставаться в локальном режиме, чтобы не отправлять задачи самому себе.

Адаптер работает внутри процесса локального API: модели, кеш и арбитраж GPU
общие. Отдельный сетевой сервер обслуживает только проверку состояния, приём
подготовленного аудио, опрос результата и отмену. Все сетевые маршруты требуют
ключ; управляющие маршруты включения адаптера доступны только через loopback.

Проверки разработки:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_remote_compute tests.test_gpu_turns
npm.cmd test
```

HTTP-тесты используют изолированные настройки, настоящее соединение и
подмену вычислений модели. Они проверяют протокол, а не качество распознавания.
